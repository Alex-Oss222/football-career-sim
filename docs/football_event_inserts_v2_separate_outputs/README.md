# Event inserts, separate outputs (v2)

**Fixed requirement:** one active period briefing and one possible shared user-response page, but **one standalone dated final-result file per resolved event**, including individual trades. Never aggregate separate outcomes into one output or postpone them until the weekly game report.

Read `Implementation_Spec.md` for the routing and hard tests; `Event_Results_TEMPLATE.md` controls every separate output. The remaining files show the shared briefing inserts, shared answer surface and illustrative scenarios.

Status: proposed design. No GitHub files were changed.
