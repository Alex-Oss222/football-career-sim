# My Responses: short event answers

**Design status:** Adopted October 20, 2026 from the user's upload; built in step 5 of the [rebuild plan](../../../docs/rebuild_plan.md). One small response journal per active week or career phase, NOT a new three-page decision for each event. The journal is separate from a frozen `Game_Plan.md`. Each block is bound to a pending event ID in machine metadata and is validated before application; the user-facing page shows the issue name, not technical IDs.

**One shared answer journal does not mean one shared result.** Every closed event named here must yield a separate dated outcome page under its own appropriate event owner, linked from the week/phase index, even if the answer was “Oppose trade” or “Decline offer.”

The user may instead send the issue name and decision in chat. An authorized interface may embed these same blocks in the active answer page, but the recorded response must have one durable owner.

## [Issue name, e.g. Trade proposal from Tennessee]

**My answer:** [Recommendation / approval / refusal / counterproposal / ask for more information / wait until a stated date, if permitted]

**My football or professional reason:** [Brief explanation, or “None additional.”]

**Conditions or instructions:** [Only if needed; otherwise “None.”]

**Date answered:** [The simulated date, supplied by the runner when recorded]

Do not fill in an answer on the coach's behalf. No answer means no resolution. “Leave this open until [date]” is an explicit instruction that may allow nondependent work to proceed; it must not silently bypass a real offer deadline.

### Smallest valid answer by event

| Event | Example answer | What the answer actually controls |
|---|---|---|
| Injury creates a vacancy | “Recommend [eligible player] to Caldwell. Keep [player] in [role].” | Football recommendation or role decision, not medical clearance or GM transaction |
| Trade | “I support the proposal only if [football condition].” | Recommendation; Caldwell still accepts, counters or rejects |
| Player extension | “Recommend opening talks for [player], with [football priority].” | Recommendation; cannot force negotiation, agent assent or signing |
| Assistant renewal | “Offer [coach] renewal on [known budget/terms].” | Stone's staff choice, subject to contractual/budget approval |
| Assistant interview request | “Apply my standing permission instruction.” or “Advise the club to [action].” | Only where NFL-era rules and contract/club authority allow discretion |
| Stone's own extension | “Accept / Counter with [terms] / Decline.” | Personal career response, not the owner's final counteroffer |
| Stone's own interview | “I want to pursue / Decline.” | Personal intent, not Jacksonville's consent |
| Fired or free agent | “Ask my agent to pursue [type of work/clubs], subject to [constraints].” | Job-search instructions; the employer's termination is already decided |

### Validation rules

1. The underlying bound event exists, is visible to Stone, is still open, and actually requires his authorized part.
2. Any named player or coach, date, contract term and protected role is verified against active records and era rules.
3. A recommendation is never silently treated as an execution or external agreement.
4. The user's football choices do not change a frozen or played game sheet unless they separately and validly amend that week's game plan *before* freeze.
5. Every accepted answer is tied to the resulting event record, so the briefing and result cannot drift.
