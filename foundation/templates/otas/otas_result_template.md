# Results in the OTA and minicamp period: use the shared event result

This phase has no result form of its own. Each event resolved during the OTAs and the mandatory minicamp gets one dated result page built on the shared [event result](../event_inserts/event_result_template.md), with its fields and nothing added, written on the day it resolves, in its owner's folder: roster moves in `Team_Operations/Team/Roster`, signings and undrafted pursuits in `Team_Operations/Free_Agency`, trades in `Team_Operations/Trades`, staff in `Team_Operations/Staff` and Stone's own career in `career/Stone`. A medical decision stays in its medical record. An existing standalone transaction record that already serves as the event's result is used instead of a second page. Stone's answer, when one was needed, is on this phase's My Responses page, and the OTA Report links each result and never repeats it.

The uploaded reference that stood here repeated the shared form under other headings, so it is not kept as a form. Its four acceptance examples are tests 59 to 62 of the [OTA design](../../../docs/otas_and_minicamp.md#8-validation-tests-to-implement-not-executed). This page stays only so that existing links resolve; the build points those links at the shared form and then removes it.
