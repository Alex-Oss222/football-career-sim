# 2010-2014 yardage calibration

[Pre-build specification](2014_6_pre_build_specification.md) · [League base](2010_2014_calibration_base.md) · [Engine decisions](../runtime/2014_engine_decisions.md) · [Defect register](../runtime/defect_register.md)

**What this is.** The league record behind kernel 2014.6's yard split (batch B13, R16a and R16b) and its band rows (R16c). The artifact is `library/data/2010_2014w4_yardage.json`, built by `scripts/research/build_2010_2014_yardage.py` with a `--check` mode, under the rules of the pre-build specification (section 4, Yardage). Nothing in it is typed by hand.

**Data window.** NFL regular seasons 2010-2013 and 2014 Weeks 1-4 (games through September 29, 2014), read only through the batch B2 source gate. 2013 and 2014 Weeks 1-4 are an anonymous post-divergence league population: they enter pooled counts only. No club's, game's or player's own row is stored; identifiers are read only to count team-games.

## What the engine draws from, and what this record adds

The yard split itself is not drawn from this record. Each replayed real drive of the 2010-2014 league base (`library/data/2010_2014w4_nfl_field_position_model.json`) carries its own B3b yardage annotations: its real rushing yards, passing yards (completions only), completions, sack losses in snap order, run values and completion values in snap order with the terminal value included, and its terminal scrimmage snap. Under the profile flags `yard_split` (R16a) and `snap_values` (R16b) the engine replays them (`runtime/yard_split.py`, `runtime/kernel.py` `_yard_split`, `runtime/chains.py` `_draw`). This record supplies the band centres and the spreads their tolerances need, so a 2014.6 cohort can be graded:

- **Yards per carry, kneels included** (the NFL.com definition), with the team-game residual standard deviation of (rushing yards - pooled yards per carry x carries) and the mean carries per team-game: the ratio's tolerance is 3 x SD / (mean carries x sqrt(team-games)).
- **The completion rate, spikes counted as attempts**, and **the run share of scrimmage plays**, (carries + kneels) / (carries + kneels + pass attempts + spikes + sacks), each with its team-game Pearson dispersion: the tolerance is 3 x sqrt(dispersion x p(1-p) / N) at the cohort's own N. Batch B12 (the 2014 completion target) is not built, so the completion centre is the pool's own level; under U2 there is no completion tilt in any case.
- **Rushing yards per team-game**, kneels included, with its team-game standard deviation (tolerance 3 x SD / sqrt(team-games)).
- **The per-snap shape of non-kneel runs** (play type run, scrambles included): the shares losing yards, gaining 0, 1-3, 4-9, 10-19 and 20 or more yards. The losing, 1-3 and 20-or-more rows are graded (binomial, 3 x sqrt(p(1-p) / runs)), only on the synthetic all-club acceptance samples (plan B13, R16c); on a real cohort the engine's audit lists them as informational. The other bins and **completions of 20 or more yards per attempt** are informational.

## How each piece is counted, and the two passes

The primary pass reads nflverse through the committed loader (`league_base_2010_2014.load_rows`) and counts every offensive snap of the committed drive definition (`is_off`: two-point tries left out, no-play rows left out) per team-game: a run or kneel is a carry, a pass that is not a sack or a spike is an attempt, a sack is a sack. The build fails unless its carries, rushing yards, attempts, completions and sacks equal the committed aggregate baseline's own pairs (`library/data/2010_2014w4_nfl_aggregate_baseline.json`, pinned by sha256): the B13 centres and the base's aggregate are one count. The second pass reads nflscrapR's raw rows with separately written parsing of its own play type, yards, sack, completion and two-point columns. Both files derive from the NFL GSIS feed, so the second pass checks the parse, not an independent observation of the seasons. Every compared value agrees within two standard errors (the table below). Each centre carries its per-season counts and a homogeneity test; equal weight per event is the adopted weighting (default 1B.1), and a drift is reported, never fitted.
